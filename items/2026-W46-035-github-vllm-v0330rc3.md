## 日本語要約

vLLM 0.33.0rc3 は一週間で CUDA 13 wheels 専用、ROCm 10.0 default、Blackwell/B300 への大規模対応を同時に行う巨大 rc。Quantization セクションは `--quantization-config.moe.activation` 対応、**pluggable KV cache data types (#52670)**、**online re-quantization の NVFP4 MoE 拡張 (#60276)**、**Quark MXFP8 routed experts (#63125)**、**MoNe expert-pruning checkpoints (#50415)**、**torch MXFP8 linear backend (#51933)**、FP8 per-token-group quant 1.15-1.29x 高速化 (#61343)、**Nemotron-3-Nano NVFP4 の torch.compile 下でのガーベジ出力修正 (#61749)** を含む。DSA 系モデル (GLM-5.2) で NVFP4 KV が incorrect の既知問題あり。

## 量子化関連の変更点

- **GLM-5.3-Flash FP8 KV cache が default 化 (+9.8% end-to-end throughput, #61228)** — 新 default。
- **GLM-5.3 per-token-group quant (+2.8% ITL, #60927)**、in-place draft decode metadata (#61873)、`concat_and_cache_mla` scales skip (+1.2-3.0% TPOT on B300, #62102)。
- **Qwen3.8-Flash-Next FP8 QSA KV cache on Ampere (#60602, #60992)**、**packed NVFP4 PLE embeddings** で DGX Spark 1 台に収まる (#56273)。
- **Kimi-K3 KDA RecoverSSM CuTe DSL verify/commit kernels (SM10x, verify 記録を KV cache 外へ、KV connector 動作、#63045)**、**NVIDIA projections の online quantization (#62980)**。
- **AMD ROCm: DeepSeek-V4 MXFP4 indexer K cache が CDNA4 で default (TTFT -30.7%, #60834, #63669)**、Qwen3.8-Flash-Next **native W4A4 (1.9-2.3x, #60816)**、AITER top-k for sparse indexers on gfx950 (#61943)、FlyDSL GDN prefill default on gfx942/gfx950 (#60645)。
- **Intel XPU**: torch MXFP4 linear backend (#51965)。**CPU**: INT8 W8A8 MoE brgemm (#60740)、zentorch 2.14.0.1 AVX512-FP16 float16 (#61411)。
- **DeepGEMM MegaMoE with NVFP4 routed experts (#61538)** + warm-up kernels (#60468, #61657)。
- **FA4 sparse MLA decode at ≤16 query heads/rank on Blackwell (default, #55866)**。
- **LoRA**: expert LoRA for MXFP4 MoE on `flashinfer_trtllm` (#61979)。
- **Batch invariance**: compressed-tensors W4A16/W8A16 (#60524), online FP8 MoE (#57092)。

## 影響範囲

- **BREAKING**: CUDA 13.0 wheels 専用、CUDA 12.9 廃止 (#62575)。Medusa / MLP speculator 削除 (#61701)。Ray V2 executor 唯一化 (#61712)。
- **New default**: GLM-5.3-Flash FP8 KV cache、ROCm AITER FP8/FP4 BMM for MLA off (#53123)、`VLLM_ROCM_MONO_DECODE` → `--monokernel` (#61082)。
- 既知問題: DSA モデル (GLM-5.2) で NVFP4 KV cache の出力が誤る。

## 注目度コメント

**focus の NVFP4 / kv-cache-quant / moe-quant が同一 rc に同居**。W45 の v0.33.0 系続きで、「GLM-5.3-Flash FP8 KV cache が default」は focus の KV 量子化が engine default まで押し上がる象徴。gemma-4 側は modality 系 (Gemma4Unified batched embedding #60643, Gemma 4 encoder graphs 複数) 中心で focus method への直接統合はまだ無い。Kimi-K3 (K2.7 後継想定) の native modeling + NVFP4 KV は TRT-LLM と並ぶ進展。**TurboQuant / PolarQuant / QJL 言及ゼロ**(本文 grep 確認済み)。
