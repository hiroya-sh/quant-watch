## 日本語要約
今回のキャッチアップ期間で **最重要のリリース**。独立した「Quantization」セクションを持ち、**online quantization**(モデルロード時にその場で量子化)の整備、NVFP4 の MoE/KV 周りの前進、そして **AMD ROCm 側に 4-bit TurboQuant KV cache 用の decode-attention カーネルが入った**のが目玉。

## focus 突合(release body 全文スキャン・必須手順)
- **TurboQuant: 該当あり** — `FlyDSL decode-attention kernel for 4-bit TurboQuant KV cache (#47896)`(AMD ROCm セクション)
- **NVFP4: 該当あり**(下記多数)
- **google/gemma-4: 該当あり** — vision tower LoRA for Gemma4 (#42662)、Gemma3n/Gemma4 の可変長音声バッチ padding (#50958)、Gemma 4 の次期 Transformers 互換 (#49797)
- PolarQuant / QJL: 本文中に出現なし

## 量子化関連の変更点

### Quantization セクション
- **Online quantization**: online MXFP4 対応 (#49347)、online weight scale を TP 間で共有 (#49764)、online NVFP4 expert packing の精度保持 (#50029)、online NVFP4 MoE カーネルのリロード間再利用 (#50074)
- **NVFP4**: CUTLASS による **batch-invariant NVFP4 MoE** (#40372)、**KV 4-over-6 scale search (#45187)**、CuTeDSL MoE の SwiGLU-OAI / ReLU2 活性対応 (#47106)、`out_dtype` をモデル dtype に一致 (#48861)
- **新カーネル**: block-wise `scaled_mm` (#49932)、DeepSeek-V4 の **AMD Quark NVFP4** + エミュレーションカーネル (#47972)
- **修正**: dynamic INT8 **W8A8 MoE 設定が W8A16 として構築されていた**バグ (#50833)、TritonExperts のクラッシュ (#51411)、FlashInfer CUTLASS 向け MXFP4 変換 (#51038)、MXFP4 の fp32 weight scale と per-expert チェックポイントマッピング (#51419)、fused block-scale の向き (#50727)

### KV cache 系
- **Tiered KV cache offloading**: ディスクオフロード (#49644)、`module_path` による out-of-tree の二次ティア管理 (#51007)、二次ティアの部分ロード結果 (#50321)、tiering メトリクス (#48798)、並列度非依存のオフロード用 canonical CPU レイアウト (#48414)
- KV-cache レイアウトのリファクタで **backend が KV packing を publish** する形に (#51612, #51704)
- MLA chunked context のリクエスト単位スケジューリング (#50613)、partial-tail prefix reuse (#50507)
- Model Runner V2 に **multi-layer MTP KV cache 対応** (#50062)

### AMD ROCm
- **`FlyDSL decode-attention kernel for 4-bit TurboQuant KV cache` (#47896)** ← focus method
- AITER + FP8 推論を GFX120x で有効化 (#43615)、gfx950 の Triton sparse-MLA decode 最適化 (#52212)、gfx942 の fp8 MQA logits カーネル (#49544)、Kimi-K3 KDA decode の fused カーネル (#50654)

### その他
- NVIDIA: GB10 の fused-MoE FP8 チューニング設定 (#52502)、FlashInfer XQA decode を SM12x で (#49718)
- Intel XPU: INC DeepSeek V4 向け **MXFP8 linear weights** (#48476)、Arc Pro B70 向け Mamba SSU 設定チューニング (#50534)
- CPU: **s390x で GPTQ / AWQ 有効化** (#51148)、MXFP4 の block scale 折り込みを4命令→2命令に (#51583)
- 新モデル: Ling 3.0 Flash(BF16/MTP/parser)+ FP8 版 (#51265) + **hybrid MXFP4 routed experts** (#52114)、Muse Glimmer、Dots3
- 修正: **MiniMax-M3 の NVFP4 推論** (#48929)、compressed-tensors の FP8 MoE SwiGLU パラメータ (#46845)

## 影響範囲
- **TurboQuant KV が W34 の `#50533`(KV quant mode)に続いて W36 でカーネル実装まで到達**。ただし今回は **AMD ROCm 側**。NVIDIA 側の対応状況は本リリースノートからは読み取れないため、`--kv-cache-dtype turboquant_*` の CUDA 動作は別途要検証。
- W8A8 MoE が W8A16 として構築されていたバグは、**v0.28.0 未満で INT8 MoE を評価していた場合の測定値が信用できない**ことを意味する。
- ModelOpt 側は 0.46.0 で「vLLM 0.24+ の `RoutedExperts` 移行」に追随済み。

## 注目度コメント
**最強推し議題候補**。focus の TurboQuant / NVFP4 / kv-cache-quant / moe-quant が1リリースに同居している。特に「online quantization」の整備は、量子化済みチェックポイントを配布せずに評価を回せるという意味で、自前実装をしない現方針と相性が良い。
